Integration architecture: choose a pattern

This section is for architects integrating LibreSign into an existing application. LibreSign is free and open-source software; deploying it does not require a commercial service. Optional hosting, support and third-party delivery gateways are separate from the LibreSign API. Your application may retain its UI, authentication and business workflow.

You are reading the guide for LibreSign 13.4.9 on Nextcloud 33. Concepts here apply to the available release line; the OpenAPI contract is version-specific. Confirm each request shape in OCS OpenAPI — versioned contract before implementing it.

The shared example selects the request schema for LibreSign 13/14 (mandatory) or 15/development (requirement). The discovery step requires default LibreSign storage and requester WebDAV access. Verify these prerequisites on the target installation. Native completion events are documented only for development; the workflow uses OCS polling.

Contract and ownership boundaries

Practical API integration is already documented in External email signers: integration, with examples and tests pinned to each published LibreSign release. Use that guide for requests, mail invitations, status polling, validation and authenticated WebDAV download.

Native webhook support is release-dependent. Consult Notifications, completion and document recovery for the event availability on this release and the release-specific Webhooks manual where one exists. A compiled application event or passing unit test alone does not prove successful outbound HTTP delivery.

No recommendation here requires direct database access, credential sharing with a signer, or disabling Nextcloud authorization. Use supported OCS and Nextcloud file APIs instead.

For details of Nextcloud’s request transport, see the Nextcloud OCS API overview.
